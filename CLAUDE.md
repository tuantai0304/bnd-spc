# CLAUDE.md — Space Travel

Coding-challenge solution (see [README.md](README.md)): a federation dispatches 4 shuttles
between 5 planets. Each shuttle carries **20 life forms OR 4000 kg** — whichever cap is hit
first. The system must pick shuttles "efficiently" (fuel), persist travel history, and run
with one command and no database server.

## Stack

- **Backend:** .NET 10, ASP.NET Core Minimal APIs, EF Core 10 + **SQLite**, FluentValidation,
  built-in OpenAPI (`/openapi/v1.json`, Development only). No MediatR, no AutoMapper, no Swashbuckle.
- **Frontend:** Vite + React 19 + TypeScript strict, TanStack Router (file-based), Zustand,
  Tailwind **v4** (CSS-configured), types generated by `openapi-typescript`.
- **Tests:** xUnit + `WebApplicationFactory`. No mocking framework — the domain needs none.

## Architecture

**Simple monolith, vertical slices, rich domain.** Chosen deliberately over layered/clean/CQRS —
see [docs/architecture-options.md](docs/architecture-options.md).

```
Features/<Slice>/   Endpoint → Validator → Handler → Mapping → Request/Response  (one folder per use case)
Domain/             Fleet (aggregate root), Shuttle, TravelRequest, LifeForm, Planet, Capacity, enums
Data/               DbContext, Configurations/, FleetRepository, DbSeeder, Migrations/
Code/               cross-cutting: Endpoints, Validation, Errors, Dispatch, Simulation, Time, Options, OpenApi
```

Three rules hold the design together:

1. **All business rules live in `Domain/Fleet.cs`.** Capacity, batching, queueing, the state
   machine. Handlers only orchestrate: acquire gate → load aggregate → call one method → save.
2. **Slices self-register.** Every endpoint implements `IEndpoint` (`static abstract Map`) and is
   discovered by reflection in `MapEndpoints()`. Adding a feature never edits `Program.cs`.
3. **The world moves on its own.** `SimulationTickService` (BackgroundService, 500 ms) advances
   shuttles via `FleetAdvancer`; a leg takes `max(1, |rankDifference|) × 3s`. There is no
   push channel — clients poll.

### Cross-cutting invariants

- **`IDispatchGate`** (in-process `SemaphoreSlim`) serialises every read-decide-write of the
  fleet, so dispatch and the tick take turns and a shuttle can never be overbooked.
- **`IClock`** — never call `DateTime.UtcNow` outside `SystemClock`; tests drive time.
- **Errors** are RFC 7807 ProblemDetails via `GlobalExceptionHandler`
  (`ArgumentException` → 400, `InvalidOperationException` → 409, else 500 with no detail leaked).
- **Config over code:** planets, shuttle names, capacity caps and simulation timings all live in
  `appsettings.json` bound to `Code/Options/*`.

### The API

| Method | Route | Notes |
|---|---|---|
| POST | `/api/travel-requests` | the only write; **always 201**, even when rejected |
| GET | `/api/travel-requests/{id:int}` | poll one call |
| GET | `/api/shuttles` | live fleet + manifests |
| GET | `/api/planets` | 5 docks, nearest first |
| GET | `/api/travel-history?page=&pageSize=` | paged log |
| GET | `/api/travel-history/stats` | trips per destination — the brief's actual goal |
| GET | `/health` | liveness |

**The one contract rule everything else follows from:** a call that no shuttle could ever carry
is a *business outcome*, not an error. It returns `201` with `outcome: "Rejected"` and is written
to history. Branch on `outcome`/`status`, never on HTTP status. `400` means malformed input only.

Statuses: shuttle `Idle | EnRoute | Arrived`; request `Queued | Assigned | InTransit | Completed | Rejected`
(last two terminal). Both serialise as strings, in the DB and on the wire.

## Commands

```bash
dotnet run --project src/backend/SpaceTravel.Api   # migrates + seeds SQLite on startup
dotnet test                                        # 52 tests
dotnet test --filter "FullyQualifiedName~SpaceTravel.Tests.Domain"   # no database needed
```

Reset state by deleting `src/backend/SpaceTravel.Api/spacetravel.db*`. Never commit `.db*` files.

## Conventions

- Nullable + implicit usings on; `sealed` by default; records for DTOs and value objects;
  private setters + factory methods (`Create`) on entities; `internal` mutators inside the aggregate.
- **Comments explain *why*, not *what*** — the existing code is dense with rationale that cites the
  BRD. Match that when touching it; don't strip it.
- Assumptions are documented, not invented: read [docs/assumptions.md](docs/assumptions.md) before
  deciding an open question, and add to it when you make a new call.
- Detailed rules load automatically per area: `.claude/rules/backend.md` (`src/backend/**`) and
  `.claude/rules/frontend.md` (`src/frontend/**`).
